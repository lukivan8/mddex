# Farming planner

`/resources/planner` reads a saved build on the current device or resolves an existing shared build link. It does not create a new saved build, change equipment, update the active builder workspace, or publish a share. Variants are planned independently. Local storage uses the existing validated build collection and its legacy migration; unreadable records remain preserved.

Targets are distinct equipped item and enchantment slugs. Talismans and enchantments remain visible in location pools; their top item icons identify one-time acquisition through a green indicator and tooltip. Collected talismans and enchantments default to disabled using the existing local tracker’s `:collected` marks. Tracker changes sync across tabs and on return to the page. Per-build/variant manual selection overrides remain available and reset when selecting another build or variant. Regular equipment tracker marks do not disable farming targets. The planner never writes to the tracker, including when a save is malformed or unavailable. Variants use the same Roman numeral selector as the build page. Item toggles appear below the build controls as 56px square icons in slot order, wrapping horizontally on narrow screens. Names, slots and one-time/tracker status are available in tooltips and accessible labels. Repeated slots share a toggle; random effects are rolls on equipment rather than separately acquired items. Route items show the selected build effect icons below their names, retaining separate combinations for repeated equipment slots and preserving missing effect references. Missing slugs remain visible. The planner requests selected build item details from the session-pinned catalog, plus entrance-location shards needed to resolve dungeon/rift artwork. Artwork resolves by published source URL and artwork key through the shared catalog-detail helper; each referenced location is loaded once per batch. Partial detail failures are retryable, and toggles never refetch details.

`farm-planner.ts` projects acquisition evidence through the existing detail/drop chance helpers. Location, mob, dungeon, rift and quest reward sources participate in the farming plan. Quest stops link to the quest graph and retain first/repeat completion conditions and reward selection rules. Items without farming locations retain their other acquisition notes and retryable loading errors. Chest instructions, known reward selection rules and rarity conditions remain visible. Unknown probabilities are omitted. Published artifact area pool shares appear in catalog details and planner routes and participate in drop-rate tie breaking. These cover all artifact rarities without applying Unique gear conversion or inferring per-kill odds.

The optimizer finds the exact minimum number of stops covering all selected targets with known farming sources. Dynamic programming is bounded by the build's 12 equipment and 6 enchantment slots. Equal-stop covers prefer known numeric item odds, normalized per target against its best catalog source. The dynamic-programming tie score sums preferences for newly covered targets. Missing odds add no rate preference; they are not assumed to be zero drop chances. Unique item estimates multiply the published base pool share by the owner-selected 5% regular or 10% boss conversion; published catalog outcome probabilities remain unchanged in item details. Remaining ties use overlap and name order. Stops are displayed by coverage. Each target appears in the main loot list only at its first stop; later overlaps remain collapsed under “Acquired before”. This is a planning assumption, not a persisted record or guarantee that a drop has occurred. This is not a shortest travel path or an expected-time optimizer: there are no verified clear times, travel distances or probabilities for every acquisition source. Uncovered items remain visible below the plan. Only the automatic primary plan is shown; alternative routes and manual editing are not included. The page omits the former per-item acquisition and unique-chance sections.

For future location farming guides, attach authored data by `FarmStop.key` (catalog slug where available; otherwise source type plus normalized name). Keep dungeon/rift guides separate from their entrance area's outdoor guide. A guide can be rendered inside the stop card without changing item projection or coverage. Authoritative timings or constraints would need a separate objective before changing the optimizer's equal-stop-cost model. Source attribution remains in the published catalog; guide authorship should remain with future guide data.

Verification: unit tests include a greedy set-cover counterexample, source projection, deduplication and the 18-target boundary. Fixture browser coverage exercises saved builds, variants, item toggles, both share formats, quest links, storage preservation, targeted detail requests and mobile overflow.

## Initial implementation validation

- `npm run check`: typecheck and lint passed; 271 unit tests passed.
- `CI=true npm run test:e2e -- e2e/planner.spec.ts --workers=1`: initial run failed on a test-script expectation for Clear all after unchecking an item (the control correctly offered Select all). The script was corrected and the exact rerun passed 2/2.
- `CI=true npm run test:e2e -- e2e/planner.spec.ts e2e/quests.spec.ts --workers=1`: 5/5 passed, covering desktop/mobile planner and quest navigation regression checks.
- `npm run build`: production build passed. Preview on port 3200 returned HTTP 200 with the planner heading and input UI present in rendered HTML. The temporary preview server was stopped.
- Real catalog smoke check on the existing local development server: a saved 17-target build produced four overlapping farming stops with catalog artwork, known drop-rate labels and separate talisman acquisition options. This does not validate game drop rates independently of the catalog.

Boss recommendations are visible only with “Farm bosses” enabled. The owner-supplied recommended boss mapping covers Rainy Plains, Lullaby Hills, Howling Woods, Frozen Highlands, The Deep Dark and Singer's Meadow. “Farm bosses” prioritizes all weapons, armor and artifacts in those area pools (owner-confirmed eligibility), minimizing boss stops before planning remaining targets. Other categories and acquisition types follow the boss stops. Unique farming estimates use owner-selected conversion assumptions: 10% for boss stops and 5% for other sources, multiplied by the published base pool share. Other area average probabilities are not displayed as boss probabilities. Catalog detail odds retain the published source calculations. Boss references use compact-index artwork and catalog links without fetching boss details.
